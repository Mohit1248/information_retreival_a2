# Data

## `toy/` -- local development set (ships with this repo)

The same 20-document, 6-query, graded-qrels toy set used in Assignment 1
(`corpus.jsonl`, `queries_dev.tsv`, `qrels_dev.txt` -- identical files,
identical format), plus a NEW `candidates_dev.jsonl` specific to this
assignment. Reused deliberately: you already have working
tokenisation/loading code for this exact corpus from Assignment 1, and it
is small enough that a correct implementation should get every judged
query essentially right.

**The toy set is not the assignment corpus and its scores do not count
toward your grade.** Use it to catch bugs, not to tune lambda or mu.

Files:
- `toy/corpus.jsonl` -- one JSON object per line: `{"doc_id": ..., "text": ...}`
- `toy/queries_dev.tsv` -- `qid<TAB>query text`
- `toy/qrels_dev.txt` -- TREC qrels format: `qid 0 doc_id relevance`
- `toy/candidates_dev.jsonl` -- one JSON object per line:
  `{"qid": ..., "candidates": [[doc_id, score], ...]}`, best first. This
  is the candidate pool `score_candidates()`/`relevance_model_feedback()`
  rerank -- see `harness/candidates_io.py` and `docs/GRADING.md`, "Where
  the provided candidates come from". On the toy set this happens to be
  ALL 20 documents (full recall, so you can debug without a first-pass
  retrieval bottleneck); the real corpus's candidates file is a genuine
  top-100, which will not have 100% recall of every relevant document --
  a realistic constraint your reranker has to live with, not a bug.

## The real assignment corpus

Run `python scripts/download_full_corpus.py` to fetch the actual
assignment collection via `ir_datasets` (see the assignment spec, Section
6, for the exact dataset name announced for this offering). Writes
`corpus.jsonl`/`queries_dev.tsv`/`qrels_dev.txt` into `data/full/` in the
same format as the toy set -- your code does not need to change between
the toy set and the real one.

**`data/full/candidates_dev.jsonl` is released separately by course
staff, not generated by `download_full_corpus.py`.** Unlike the corpus
and topics/qrels (public via `ir_datasets`), the candidates file depends
on an undisclosed reference retriever (`docs/GRADING.md`) that only
course staff can run -- you cannot regenerate it yourself, and
`download_full_corpus.py` does not try to.

**Held-out topics are never distributed**, and neither is their
candidates file or the real Track C noise-injection recipe -- see
`docs/GRADING.md`.
